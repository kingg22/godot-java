# Generic virtual method dispatch (issue #20)

## Problem

Godot calls a GDExtension class through two callbacks registered at class-registration time:
`getVirtual(class_userdata, funcName, hash) -> GDExtensionClassCallVirtual?` (asked once per
virtual-method name; returning `null` makes Godot use its own C++ default) and the trampoline itself
(unmarshal raw args, call the Kotlin method, write the return value back).

Previously this was hand-hardcoded to exactly `_ready`/`_process` on `Node`
(`NodeVirtualCalls.kt`/`NodeVirtualDispatcher.kt`), and every `@Godot` user class got the *same*
`NodeVirtualDispatcher.getVirtual` regardless of its actual base class or which methods it overrode —
broken for any non-`Node` base, and for every virtual beyond those two.

## Design

1. **Codegen** (`VirtualCallImplGen` + `NativeEngineVirtualCallsGenerator`) generates, per engine class
   with virtual methods, an `<EngineClass>VirtualCalls` object with one `GDExtensionClassCallVirtual`
   trampoline per *supported* method, and marks the corresponding `open fun` stub with
   `@GodotVirtualMethod(godotName)` — but only when supported (see matrix below). Unsupported methods
   are left unannotated, so they're structurally never wired for dispatch: Godot's own default runs.
2. **KSP processor** (phase 3/4) walks each `@Godot` class's declared overrides, follows
   `KSFunctionDeclaration.findOverridee()` up to the annotated root, and generates a bespoke
   `staticCFunction` `getVirtual` per user class referencing only the trampolines for methods it
   actually overrides.

`staticCFunction` lambdas in Kotlin/Native cannot capture, so there is no shared runtime dispatch
table — each user class gets its own literal `when` block generated by KSP, exactly mirroring the
existing per-class property getter/setter trampolines in `GodotBindingGenerator`.

## Type-support matrix

Scale: 1437 virtual methods across 106 engine classes (`extension_api.json` v4.7.1). Supported
uniformly across all 106 classes — no per-class hand-listing, only per-*type-category* gating:

| Direction | Supported | Deferred / unsupported |
|---|---|---|
| Argument | CVar primitives, `bool`, `enum::`/`bitfield::`, engine-class/singleton object refs (nullable per `arg.isNullable`, matching `NativeMethodGenerator`), all opaque builtins (String, StringName, RID, Vector2/3, Dictionary, Variant, Transform3D, ...) wrapped by reference (no ownership) | `void*` (~19 methods, no verified pointer-indirection semantics for the read direction — risk is a native segfault, not a compile error, so skipped rather than guessed); native-structure-typed args |
| Return | `void`, CVar primitives, `bool`, `enum::`/`bitfield::`, engine-class (written via `.rawPtr`), `Variant` (via `VariantBinding.newCopyRaw`), every other heap-backed builtin with a copy constructor — String/Array/Dictionary/Packed\*Array/... (placement-constructed via `VariantBinding.getPtrConstructorRaw`, see #135), `void*` (written directly — `typeResolver` already resolves it to `COpaquePointer`, see #137), `typedarray::*` (shares the plain `Array` copy-constructor fptr — a typed array is still exactly an `Array` at the ABI level, see #139) | Native-structure-typed returns |

A method is only annotated/dispatchable when **every** argument AND the return type are supported.
Partial support (e.g. skip one bad arg, keep the rest) was rejected — it would silently produce a
wrong-arity override.

Explicitly out of scope: brand-new user-declared virtuals with no engine counterpart (not coherent —
Godot only ever queries names from its own virtual method table); `getVirtual`'s `hash` parameter
verification (already ignored pre-existing).

## Where things live

- `kotlin-native/api/chore/.../api/internal/GodotVirtualMethod.kt` — `BINARY`-retention marker
  annotation. Not in `api/annotations` (that module depends *on* `api/generated`, so annotating
  generated code from there would be circular).
- `<EngineClass>VirtualCalls` objects — generated alongside each engine class, same package, same file
  set as `NativeEngineClassGenerator`'s output.
- `kotlin-native/binding/.../VirtualDispatchSupport.kt` — small capture-free helper factoring out the
  null-check + `StringName(funcNamePtr).use { }` boilerplate every generated `getVirtual` needs.
